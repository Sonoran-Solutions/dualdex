**Decision: the player storage evidence justifies a separate bounded decoder implementation
as the next engineering slice. Full integration must not proceed.** Two simultaneously occupied
slots followed their Pokémon as entire 76-byte records during an ordinary party switch, repeated
in two processes. Exact-ROM accessors independently establish byte count and 76-byte indexing.
HP damage, PP consumption, potion healing, in-game saving and a new-process cartridge load passed.
Three through six occupied slots, count decreases, fainting and several special cases remain untested.
The named enemy count was zero during a visible wild battle: general enemy authority is contradicted.
No production decoder/profile/trusted hash, memory permission, data pack or calculator changes.
#59 stays open; all related evidence PRs remain draft/unmerged without auto-merge.

## Evidence vocabulary and identity

**STATIC**: read from the pinned exact ROM's symbols/instructions. **OBSERVED**: paused capture
or manually checked UI in a specified local experiment. **SYNTHETIC**: invented bytes in CI.
**REPORTED**: historical/public-source lead without independent exact-release confirmation.
**CONTRADICTED**: observation refutes the stated generalization. **NOT_VERIFIED**: an unmet gate;
**NOT_RUN** records a scenario that was not exercised. “VERIFIED stride” below means the combined
static indexing and observed two-slot storage result, not every Pokémon/mode or full support.

and the authorized local base. “Expansion” is not the established release label. The inherited

## Exact-ROM accessor investigation

[party-accessors-v3.json](../tools/rom-evidence/evidence/party-accessors-v3.json) is generated by
[rowe_static.py](../tools/rom-evidence/rowe_static.py). It contains semantic results, addresses and
span digests, never ROM instruction bytes. Investigation used local GNU ARM objdump 13.2.Rel1,
Thumb decoding, literal references and dispatch tables; GPL implementations were not copied.
Numeric accessor selectors below are facts from that ROM's control flow, not symbols invented
from the older source. A minimal independent immediate-load/shift verifier checks the selected
paths and refuses any ROM identity mismatch. It is not a complete decompiler/control-flow proof.

- At `0x0809BE38`, the player-count recomputation path clears `0x02025125` with STRB,
  reads it with LDRB at `0x0809BE52`, compares the index with 5, multiplies by 76 at
  `0x0809BE5C`, and addresses `0x02025128 + index*76`. The increment is also STRB.
  An independent loop at `0x08018250` uses the same multiplication/base and byte count.
  The player-add path near `0x0809BD40` indexes/copies 76 bytes and updates count with STRB.
- Party accessor `0x0809AF5C` uses a dispatch table at `0x0809AF7C`; fallback box-field
  accessor `0x0809B120` uses the selector table at `0x0809B13C`. Selected table entries are
  checked against their extraction targets. Full PID/OTID use word loads at `0x0809B2C0/C4`.
- Species selector 11 loads the halfword at +28 and keeps 12 bits (`0x0809B4D0`). Selector
  65 has an egg-substitution branch. Form selector 89 reads word +28, shifts left 15/right 27,
  keeping bits 12..16. Nature selector 90 explicitly reads byte +39, shifts left 25/right 27,
  keeping bits 2..6: independent storage is established even though observed values equal PID%25.
- Move selectors 13..16 extract 10 bits from +20 bits 0..9, +24 bits 0..9 and 10..19,
  and +30 bits 1..10 (equivalently word +28 bits 17..26). Move 1 shares a mask tail via
  a branch. Move paths include flag-dependent override branches; this proves stored IDs,
  not every effective move in every mode. Experience selector 25 extracts word +20 bits
  10..30; bit 31 is excluded rather than inferred from a normal value.
- Status selector 55 reads all 32 bits at +56. PP selectors 17..20 use byte loads at
  effective offsets 52..55. Level's stored-byte path reads +60; the accessor also contains
  a conditional override. HP/stats use halfword loads at +62,64,66,68,70,72,74.
- The non-egg nickname path copies source +8, indices 0..11, and terminates the destination
  separately. Twelve stored bytes are established; maximum displayed name length, all glyphs,
  egg behavior and padding semantics remain NOT_VERIFIED.

Reproduce semantics with `python3 tools/rom-evidence/rowe_static.py --rom /private/rowe.gba`.
For independent private inspection use `arm-none-eabi-objdump -D -b binary -m arm -M force-thumb
--adjust-vma=0x08000000 --start-address=0x0809AF5C --stop-address=0x0809B580 /private/rowe.gba`.
Keep disassembly local. Static storage widths are not evidence that high-bit runtime values,
all flags, eggs or nonzero forms have been observed.

## Cartridge persistence and relocated save blocks

The save movie exits the party screen, presses the UI's **START Save**, waits for game saving,
then flushes the experiment's cartridge RAM using the existing host API. Select did not save
in an earlier exploratory attempt; that input was rejected by the observed UI behavior.
The observer reserves a new `cartridge.sav` exclusively and writes an experiment marker binding
ROM/save hashes. It refuses overwriting any existing cartridge or marker. This uses only new
disposable data, never an existing player save.

Before saving, live count is 2, but candidate saved-copy count at SaveBlock1+`0x234` is 1 and
its party at +`0x238` differs. After in-game saving, count becomes 2 and **all 456 bytes** of the
candidate copy equal live party. SaveBlock1 moves `0x02026460`→`0x02026478`, SaveBlock2
`0x02025720`→`0x02025738`. The second save execution repeats the same equality/permutation.
This independently observes the copy/count locations for these saves; count field's serialized
allocation/width and other save versions are not established by reading its low byte.

After that saving process exited, `rowe-party-reload.movie` launches a new process with
`--load-cartridge`; no initial state is supplied. The Continue menu shows A / Pokédex 2. On
Continue, count is 2 and both entire records/order/identities/HP/PP survive byte-for-byte.
SaveBlock1/2 are `0x02026494/0x02025754` at Continue and `0x0202648C/0x0202574C` in the field;
the observed +`0x238` copy still matches live party. A prior reload navigation script reached
Trainer Skills instead of the roster despite successful cartridge loading; the final movie
corrects that UI route and captures both Pokémon's summaries. This is actual in-game cartridge
persistence. The initial private checkpoint used to create the two-slot save is explicitly
separate from the new process's cartridge bootstrap.

## Future native player decoder contract

This is an implementation contract for an **isolated raw player-slot decoder first**, not
permission to register the ROM or wire Android/JNI/production dispatch.

1. Caller supplies a pointer plus exact length **76**, read from the independently validated
   player region `[0x02025128, 0x020252F0)`, capacity six slots. No casts to compiler bitfields,
   no 100-byte native container reads, XOR, checksum or scan-based discovery. Decode explicit
   bounded little-endian loads using only the widths in the table. Output raw release IDs/form,
   raw name bytes, stored level, raw status and exact identity words; unknown bytes stay unknown.
2. Snapshot caller supplies independently read u8 count from `0x02025125`, rejects >6, and
   reads count/data/count while emulation is paused on its owner thread. Require repeated data
   equality or an equivalent generation boundary. Capacity is 456 bytes; require every counted
   slot to be complete. Zero means no active slots even when old species/records remain.
   Counts 3..6 are statically allowed, runtime NOT_RUN; do not claim those as observed fixtures.
3. Never accept a short/oversized slot, overflowing span, mismatched count, unmapped read, torn
   record, unverified ROM identity or wrong decoder/stride dispatch. Reject the whole active
   snapshot on a failed occupied slot; do not compact, skip, scan or reuse a last-good party.
   PID/OTID zero are not automatic invalidity; their full meanings are not all verified.
4. Separate byte decoding from semantic validation. Raw width extraction must preserve unknown
   values. A future ParsedPokemon adapter must refuse species/form or move translation without
   a verified exact-release mapping, out-of-domain stored level/nature, invalid HP/maxHP or
   unknown critical mode/egg/override interpretation. Do not infer ability, SID, shiny, gender,
   item, PP maximum, experience curve, checksum or status meanings from unproven fields.
   Neither a plausible Pokémon nor a matching header grants production trust.
5. Existing bounded `pokemon_text` behavior can be adapted only after a twelve-byte input,
   terminator and glyph policy is validated; do not assume vanilla nickname length. Future
   transport must distinguish stored level/move values from flag-dependent accessor overrides.
   Decode no unknown bits as booleans or default capabilities. No enemy decoder in this slice.
6. Test isolated C decoding with invented boundary sentinels (including adjacent-bit isolation,
   all 76 truncations, high PID/OTID bits and PP byte high bits), two-record reorder and stale
   excluded tails through the #190 ROM-free map harness. Keep synthetic domain checks separate
   from runtime proof. Audit every counted-loop, fallback/scanner and JNI call before any later
   production dispatch; retain existing FireRed/Emerald/H&S behavior and failure policy.

## Reproduction and validation

See [the tool README](../tools/rom-evidence/README.md) for commands and private-data restrictions.
The committed critical scripts require the locally retained ordinary-gameplay checkpoints for
reorder/battle and the exclusive experiment cartridge for reload. They are deterministic from
those checkpoints; fresh setup/catch is not portable or fully frozen. Reproducing on another
machine means first creating its own two-slot disposable game/compatible checkpoint and recording
its own UI/identity hashes, rather than treating these Pokémon as universal goldens. The original
private checkpoint SHA binds the reported execution; that state cannot be distributed in Git.

The existing hosted CI trigger also allows this stack's parent branch while #191 remains
unmerged, so exact-head CI can run without retargeting the draft to main. Job commands are unchanged.

Canonical `./ci.sh all`, `./ci.sh source-check`, `./ci.sh fixture-test`, focused evidence tests,
diff check and exact-head hosted CI results are recorded in the PR handoff. CI uses only invented
bytes and sanitized metadata. Passing it validates the tools/contracts and regressions, never
uncaptured gameplay or the actual layout by itself.
